# SAM/SECURITY seed inputs (round 42, Scheme A)

The clean rebuild needs populated SAM and SECURITY databases. The
official install.wim ships EMPTY ones (8 KB, no subkeys), and round 41
proved the SAM service does NOT create the built-in accounts at boot
(r116 died on 0xc00002e3 SAM initialization failed). So the databases
are produced once, by running the official image through specialize,
and committed here as build inputs. The main build copies them into
staging (`Invoke-CleanSamSeedStep` in `Build-CleanPe.ps1`) and enables
MICPE (RID 1000) offline before the registry step.

## Contents

| File | What it is |
| --- | --- |
| `SAM` | SAM hive harvested from the seed run (MICPE in `Users\Names`, RID 1000 enabled, blank password, Administrators group) |
| `SECURITY` | SECURITY hive harvested from the same run (`Policy\Accounts` populated) |
| `manifest.json` | Source + SHA256 of both hives; the build step verifies the hashes before copying |
| `README.md` | This file |

## How they were produced

`Invoke-CleanSamSeedRun.ps1` on CI (seed job in `build.yml`,
`seed=true`): UUP dump 22621.1105 Professional zh-cn → DISM-apply
install.wim to a VHD → `sam-seed-unattend.xml` (specialize + OOBE:
UserAccounts creates MICPE, AutoLogon signs it in, no network)
→ QEMU boot to the desktop → clean shutdown → harvest
`V:\Windows\System32\config\SAM` + `SECURITY` from the VHD →
structure verified with reg.exe → committed here.

Nothing comes from the Ramos reference PE: Ramos is only a reference
for structure, never a source. No hive was hand-built;
both databases were generated by Windows' own specialize flow.

## Privacy note (read before sharing)

The repo is temporarily public (user decision 2026-11-25, to keep
Actions running on the free tier). These hives contain a machine SID
(from the one-off specialize run) and system DPAPI keys generated
during that run, plus the MICPE account record (blank password).
That is the same class of data any installed Windows carries; it is
NOT a copy of any real machine's credentials, and the seed VM was
destroyed after the harvest. Even so, do not copy these files into
another project. When the build works and the repo goes back to
private, this note stays as the record of where the hives came from.

## manifest.json shape

```json
{
  "source": "UUP dump 22621.1105 professional zh-cn, specialize run on seed/sam-seed-r42 (run <n>)",
  "created": "2026-11-27",
  "sam": { "bytes": 131072, "sha256": "<lowercase hex>" },
  "security": { "bytes": 32768, "sha256": "<lowercase hex>" }
}
```

Re-run the seed job only if these hives ever need regenerating
(same source, same unattend). Do not edit the hives by hand.
