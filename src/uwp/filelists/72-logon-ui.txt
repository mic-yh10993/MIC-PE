; --- Administrator shell launcher ---
; boot.wim ships neither runas.exe nor termsrv.dll. Without termsrv.dll the
; WTS API has no provider, so tsdiscon.exe (WTSDisconnectSession) can never
; switch the console out of the SYSTEM session - it returns at once and the
; screen stays on the bootstrap cmd. The shell is therefore created directly
; with an Administrator logon token: runas.exe -> CreateProcessWithLogonW ->
; seclogon. That yields a genuine LSA logon session, which is exactly what
; explorer.exe needs (a duplicated SYSTEM token is what produced "a specified
; logon session does not exist"). Signed Microsoft binary, taken from the
; donor install.wim like the rest of this list.
Windows\System32\runas.exe

; --- LogonUI XAML runtime (v6: real logon, not tsdiscon) ---

; CRITICAL_PROCESS_DIED (0xEF) at the boot logo. imageres.dll must come from
